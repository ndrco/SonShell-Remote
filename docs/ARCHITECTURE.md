# Архитектура и решения

## 2026-10-19: отделение GUI от SDK

SonShell остаётся отдельным процессом. Qt не зависит от proprietary headers,
ошибка SDK не завершает GUI. GUI владеет повторным подключением. Процесс не равен
подключённой камере: действия доступны по событиям backend. После восстановления
повторно применяются Auto Sync и Live View.

GUI: MainWindow (интерфейс), CameraSession (процесс и состояния), SettingsStore
(настройки), ImageViewer (масштаб/панорамирование), PhotoLibrary (готовые JPEG).
Модули тестируются без SDK.

Встроенный Live View: backend получает JPEG из SDK и атомарным rename публикует
последний кадр в приватном временном каталоге. Qt читает только готовый файл,
не встраивает OpenCV/X11 окно. Headless backend означает отсутствие OpenCV, поток
GUI доступен. Кадры не накапливаются. Протокол — в PROTOCOL.md.

## Учётные данные

Флажок разрешает сохранение обоих полей. Без него они живут в памяти до закрытия
окна, в том числе для переподключения. Снятие флажка сразу удаляет сохранённое.
Новый проект использует отдельные настройки. Файл имеет права 0600, каталог 0700;
шифрования на диске нет, подсказка флажка это объясняет. Пароль не попадает в argv
и журнал: backend получает окружение, читает и удаляет переменную до SDK Init.
Keyring запланирован отдельно.

## 2026-10-19: установка на чистую Ubuntu

Пакет DEB включает приватный backend и runtime SDK, Qt и системные библиотеки
устанавливает apt. Зависимости ELF вычисляет CPack/dpkg-shlibdeps, динамические
Qt platform/image plugins указаны отдельно. Install RUNPATH использует $ORIGIN,
без абсолютных SDK путей. Цель первой сборки — Ubuntu 24.04 amd64. Другие Ubuntu
и ARM требуют собственных пакетов и матрицы проверок. Перед первым соединением
GUI показывает условия Sony SDK, включая требуемые Sony согласия; полный HTML
и OSS notices устанавливаются с приложением.

SDK libmonitor_protocol.so загружает соседнюю libmonitor_protocol_pf.so и не имеет
собственного RUNPATH. CameraSession задаёт LD_LIBRARY_PATH только дочернему backend
(его каталог и CrAdapter), затем сохраняет пользовательскую часть пути. Это также
покрывает transitive dlopen без изменения vendor binaries и /etc/ld.so.conf.

## 2026-10-21: медиатека и студийная съёмка

Для EXIF/встроенного RAW JPEG используется системный ExifTool отдельным процессом
вместо ранее предложенного Exiv2. Это сохраняет границу зависимостей GUI/SDK,
даёт поддержку Sony MakerNotes и не требует нового C++ ABI. Процесс только читает
заданные теги, без shell и пользовательского ExifTool config. Таймаут, отмена и
лимит результата ограничивают работу над повреждённым файлом. Для RAW явно
показываются размеры встроенного JPEG; проявления сенсорных данных пока нет.

Индекс и декодирование выполняются в фоновых задачах Qt. Результат содержит
поколение каталога/запроса: поздний результат не подменяет выбранный снимок.
Галерея объединяет RAW/JPEG только в одном каталоге и с одним именем без расширения.
Кэш миниатюр ограничен; полные оригиналы не сохраняются в кэше.

Скачивание идёт в скрытый staging на той же файловой системе, готовый файл
публикуется rename после SDK Result_OK. Только после публикации GUI получает
событие с путём; студийный таймер запускается после декодирования оригинального
JPEG (или подписанного RAW preview), а Sync All не включает студийный просмотр.

QObject-дети живут дольше C++ полей окна. Перед разрушением MainWindow отключает
callbacks дочерних объектов к себе, затем останавливает таймеры и сеанс. Деструктор
CameraSession отключает обработчики QProcess до waitForFinished, поскольку
QProcess синхронно испускает finished даже во время ожидания в деструкторе.
Иначе callback обращается к уже уничтоженному списку действий/StudioReview.
Этот случай найден AddressSanitizer при закрытии окна галереи.
