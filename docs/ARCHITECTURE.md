# Архитектура и решения

## 2026-10-19: отделение GUI от SDK

SonShell остаётся отдельным процессом. Qt не зависит от proprietary headers,
ошибка SDK не завершает GUI. GUI владеет повторным подключением. Процесс не равен
подключённой камере: действия доступны по событиям backend. В 0.2/0.3 после восстановления
повторно применялись Auto Sync и Live View; решение 0.4 ниже отменяет Auto Sync в GUI.

GUI: MainWindow (интерфейс), CameraSession (процесс и состояния), SettingsStore
(настройки), ImageViewer (масштаб/панорамирование), PhotoLibrary (готовые JPEG).
Модули тестируются без SDK.

Встроенный Live View: backend получает JPEG из SDK и атомарным rename публикует
последний кадр в приватном временном каталоге. Qt читает только готовый файл,
не встраивает OpenCV/X11 окно. Headless backend означает отсутствие OpenCV, поток
GUI доступен. Кадры не накапливаются. Протокол — в PROTOCOL.md.

## Учётные данные

Флажок разрешает сохранение обоих полей. Без него они живут в памяти до закрытия
окна, в том числе для переподключения. Снятие флажка сразу удаляет сохранённое.
Новый проект использует отдельные настройки. Файл имеет права 0600, каталог 0700;
шифрования на диске нет, подсказка флажка это объясняет. Пароль не попадает в argv
и журнал: backend получает окружение, читает и удаляет переменную до SDK Init.
Keyring запланирован отдельно.

## 2026-10-19: установка на чистую Ubuntu

Пакет DEB включает приватный backend и runtime SDK, Qt и системные библиотеки
устанавливает apt. Зависимости ELF вычисляет CPack/dpkg-shlibdeps, динамические
Qt platform/image plugins указаны отдельно. Install RUNPATH использует $ORIGIN,
без абсолютных SDK путей. Цель первой сборки — Ubuntu 24.04 amd64. Другие Ubuntu
и ARM требуют собственных пакетов и матрицы проверок. Перед первым соединением
GUI показывает условия Sony SDK, включая требуемые Sony согласия; полный HTML
и OSS notices устанавливаются с приложением.

SDK libmonitor_protocol.so загружает соседнюю libmonitor_protocol_pf.so и не имеет
собственного RUNPATH. CameraSession задаёт LD_LIBRARY_PATH только дочернему backend
(его каталог и CrAdapter), затем сохраняет пользовательскую часть пути. Это также
покрывает transitive dlopen без изменения vendor binaries и /etc/ld.so.conf.

## 2026-10-21: медиатека и студийная съёмка

Для EXIF/встроенного RAW JPEG используется системный ExifTool отдельным процессом
вместо ранее предложенного Exiv2. Это сохраняет границу зависимостей GUI/SDK,
даёт поддержку Sony MakerNotes и не требует нового C++ ABI. Процесс только читает
заданные теги, без shell и пользовательского ExifTool config. Таймаут, отмена и
лимит результата ограничивают работу над повреждённым файлом. Для RAW явно
показываются размеры встроенного JPEG; проявления сенсорных данных пока нет.

Индекс и декодирование выполняются в фоновых задачах Qt. Результат содержит
поколение каталога/запроса: поздний результат не подменяет выбранный снимок.
Галерея объединяет RAW/JPEG только в одном каталоге и с одним именем без расширения.
Кэш миниатюр ограничен; полные оригиналы не сохраняются в кэше.

Скачивание идёт в скрытый staging на той же файловой системе, готовый файл
публикуется rename после SDK Result_OK. Только после публикации GUI получает
событие с путём; студийный таймер запускается после декодирования оригинального
JPEG (или подписанного RAW preview), а Sync All не включает студийный просмотр.

QObject-дети живут дольше C++ полей окна. Перед разрушением MainWindow отключает
callbacks дочерних объектов к себе, затем останавливает таймеры и сеанс. Деструктор
CameraSession отключает обработчики QProcess до waitForFinished, поскольку
QProcess синхронно испускает finished даже во время ожидания в деструкторе.
Иначе callback обращается к уже уничтоженному списку действий/StudioReview.
Этот случай найден AddressSanitizer при закрытии окна галереи.


## 2026-10-21: отделить съёмку от работы с картой (0.4)

Предыдущее решение о передаче оригинала до студийного просмотра приводило к
тяжёлой RAW-передаче на каждом спуске. В GUI Auto Sync удалён; старое значение
настройки игнорируется и удаляется при сохранении. После подключения посылается
`sync off`. CLI сохраняет прежние sync-команды, но в `--gui` они отвергаются,
кроме `sync off`; playback-hook и ContentsListChanged не запускают скачивание.

`CameraCard` владеет удалённым каталогом и последовательной очередью GUI;
`CameraCardWidget` — отбором, отдельными отметками брака и просмотром.
`CameraBrowser` в backend имеет один worker, snapshot каталога и отдельное
состояние callbacks. Превью использует GetRemoteTransferContentsCompressedDataFile
(Screennail), оригинал — только явный GetRemoteTransferContentsDataFile.
Отсутствие превью никогда не подменяется оригиналом. Кэш превью приватен для
сеанса, очищается при запуске процесса; GUI держит до 64 MiB изображений.
Декодирование превью идёт в Qt Concurrent с проверкой размера.

Список содержит отдельные SDK contentId/slot, файлы и размеры. Каждое действие
имеет request UUID и эпоху каталога: старый результат не применяется после
переподключения. Уведомления помечают каталог устаревшим. Перед удалением
повторно читается слот и сверяется идентичность, protectionStatus и текущий
DeleteContentOperationEnableStatus. Перед передачей при изменении карты также
проверяется идентичность. Удаление относится ко всему content, включая RAW+JPEG
и связанные файлы. Успех означает OnWarningExt CrWarningExt_DeleteContent с OK,
совпадающими slot/contentId, а не только успешный возврат API.

Оригиналы и превью сериализованы одним mutex: SDK не возвращает request ID в
transfer callback. Отмена удерживает передачу до terminal callback; без ответа
за 5 с backend помечает канал непригодным и GUI перезапускает процесс.
При закрытии worker останавливается до ReleaseDevice. Удаление с неподтверждённым
результатом прекращает очередь; повтор требует обновления и подтверждения.

Журнал `.sonshell-imports.json` хранится отдельно в каждом каталоге назначения
и записывается через QSaveFile (0600) только после SDK OK, проверки длины и
публикации. Ключ: SHA256 от метаданных идентичности (serial, если SDK его отдаёт,
иначе model+host; slot, UTC создания, пути/размеры файлов), а не хеш содержимого.
Смена рейтинга и нестабильный contentId не превращают копию в новую. «Новые»
проверяет запись и размер файла; криптографическая сверка остаётся в плане.
Карта после форматирования и файлы с полностью совпадающими метаданными могут
потребовать явного выбора другого каталога/сверки; это не доказательство равенства.

Каталог копий разделён по слотам, SDK-пути очищаются от traversal; symlinks
в пути назначения отвергаются. Коллизия имени получает суффикс. Публикация
использует Linux renameat2(RENAME_NOREPLACE), исключая перезапись даже при гонке.

Студийный просмотр по отдельному флажку получает только сжатое превью последнего
кадра и явно показывает источник. Ручной импорт не перехватывает Live View.
Это осознанная смена требования полного разрешения в пользу съёмки без обязательной
RAW-передачи; полноразмерный PostView/JPEG рассматривается отдельно.

Полный импорт «все» явно повторяет передачу всех выбранных форматов и сохраняет
старые файлы под прежними именами; новые получают суффиксы. «Новые» и «отмеченные»
используют подтверждённые локальные копии. Это позволяет повторно получить
оригиналы без ручного удаления журнала и без перезаписи существующих файлов.

Просмотр в QSplitter сохраняет индекс и размеры панелей перед fullscreen.
При возврате сбрасывается WindowFullScreen, виджет вставляется на прежнее место;
MainWindow явно возвращает все просмотрщики до закрытия и разрушения полей.
Это проверяется и при непосредственном закрытии окна в fullscreen.


## 2026-10-21: исправления по проверке 0.4 на камере

В запущенном GUI 0.4 обнаружено: очередь из двух файлов завершилась с двумя
ошибками «Небезопасный путь на карте», но индикатор остался на 50%. Backend не
передавал оригиналы: конвертация пути происходила до SDK transfer. Это было
завершение с ошибкой, а не активная передача; «Остановить» закономерно отключилась.

Пути Sony могут содержать namespace тома и обратные разделители. Namespace
первого компонента с двоеточием удаляется, разделители нормализуются, двоеточия
в оставшихся именах кодируются; переходы `..` и symlinks назначения по-прежнему
отвергаются. Все локальные компоненты остаются под выбранным каталогом/Slot_N.

Прогресс: completed — число уже обработанных файлов, percent — процент только
текущего незавершённого файла. После увеличения completed передаётся percent=0.
Виджет ограничивает значение диапазоном и не прибавляет текущий процент при
completed=total. Прежние 150/200% отвергались QProgressBar, оставляя старые 50%.
Ошибки каждой операции дополнительно попадают в журнал.

MediaSLOT2_Status недоступен на моделях без второго слота (по API reference).
Наличие слота определяется читаемым свойством статуса либо разрешённым списком,
а не отсутствием карты/нулевым enable status. Неподдерживаемый второй слот
пропускается; поддерживаемый, но неготовый слот продолжает сообщать проблему.

ImageViewer отдаёт сигналы навигации; источником порядка остаётся список карты
или proxy локальной галереи. Навигация включена только у просмотрщиков фотографий,
Live View сохраняет свои клавиши. Shortcuts принадлежат самому ImageViewer,
поэтому действуют после перехода в отдельное окно/fullscreen. При загрузке превью
список остаётся доступным; сохраняется последний запрос, устаревшее превью не
подменяет текущую строку. Копирование/удаление продолжают блокировать смену выбора.

Два столбца отметок рисует локальный delegate: белый квадрат 22 px с тёмной рамкой,
синяя/красная заливка и белая галочка. Размер области клика совпадает с отрисовкой;
системная тема и глобальные настройки не меняются.

## 2026-10-21: клавиши, справка, языки и параметры SDK (0.5)

Space/Delete принадлежат списку и самому ImageViewer, поэтому продолжают работать
после отделения fullscreen. ImageViewer лишь запрашивает отметку; CameraCardWidget
проверяет текущий кадр, защиту, доступность удаления и занятость. Delete переключает
второй столбец; вызов SDK удаления возможен только через прежний диалог подтверждения.
Shortcuts не перехватывают ввод поиска, Live View и локальную галерею. Автоповтор
отметок отключён, стандартное Space-переключение delegate убрано во избежание
зависимости от текущей ячейки/двойного переключения.

Справка — немодальный QTextBrowser с русским/английским Markdown в ресурсах Qt;
F1 доступна также из fullscreen. Внешние ссылки открываются только по клику.
Перевод GUI — стандартные QCoreApplication::translate, TS/QM и QTranslator.
Исходный язык русский, начальный выбор русский; английский каталог встраивается
через lrelease и RCC. Qt standard dialogs используют qtbase_ru из runtime пакета
qt6-translations-l10n. Язык сохраняется и применяется при новом запуске, чтобы
не пересоздавать окно, сеанс и отбор во время операции. Справка использует язык
текущего интерфейса. Добавление языков: docs/LOCALIZATION.md.

CameraControlsWidget отделён от окна; REMOTE/1 получает поддерживаемые варианты
из SDK, а не фиксированный набор для α6700. Backend camera_controls.cpp — отдельный
модуль без Qt. Указатель SDK принадлежит REPL, команды последовательно выполняются
под прежним mutex. Callback сообщает об изменении; GUI объединяет чтения и откладывает
их на время операции с картой. Список enum — GetValues/GetValueSize (GetSetValues
в 2.02 зарезервирован); каждое set повторно проверяет доступность и допустимое
значение, результат SDK явно передаётся. После результата заново читается камера;
при отказе значение возвращается, сообщение об ошибке остаётся. Старый CLI сохранён.

Клик в Live View опционален; перетаскивание продолжает панорамирование. Координаты
берутся с действующего QGraphicsView преобразования, поля исключаются; отдельного
поворота SDK JPEG нет. Backend дополнительно проверяет рамку AF по LiveViewProperty.
Недоступные метаданные отключают функцию. Во время студийного показа кадра, передачи,
ожидания команды и при потере связи AF отключён. Выбор области не выдаётся за
подтверждённую резкость: полунажатие остаётся отдельным действием. Настройки
экспозиции/физический режим камеры ради AF автоматически не меняются.

Первичные источники: локальные API Reference 2.02 `dp_AF_Area_Position.html`,
`device_property.html` и пример CameraDevice::execute_pos_xy из установленного
[Sony SDK](https://support.d-imaging.sony.co.jp/app/sdk/en/),
[QTranslator](https://doc.qt.io/qt-6/qtranslator.html) и
[Qt Linguist](https://doc.qt.io/qt-6/qtlinguist-index.html).
Заголовки и документация SDK в Git не добавлены. Context7 не предоставил
документацию Sony SDK, поэтому контракт сверялся по официальному локальному комплекту.

## 2026-10-23: отбор в fullscreen, видео и даты (0.6)

Прежний каталог отбрасывал content без RAW/JPEG/HEIF, поэтому MP4 отсутствовали
несмотря на CrGetContentsInfoListType_All. MP4 теперь включаются вместе с файлами
записи; миниатюра идёт через Thumbnail, поскольку Screennail для видео запрещён
контрактом SDK. Студийный просмотр выбирает только фотографии. Фильтр фото/видео
работает на уровне записи, RAW/JPEG — на уровне файла.

ImageView размещает QLabel оверлеи в координатах viewport, поверх изображения,
без участия в zoom/pan. Постоянная строка показывает имя и обе отметки; отдельное
сообщение на 2,3 с подтверждает действие или объясняет отказ. Оба оверлея plain
text, с контрастным фоном и без перехвата мыши. Новая выбранная строка очищает
прошлое уведомление, при загрузке превью предыдущее фото убирается: нельзя
приписывать отметку новому кадру, продолжая показывать старое изображение.

Дата каталогов берётся из SDK local creation time, при необходимости UTC,
иначе Unknown-Date. Общий capture_date.h проверяет календарную дату. Identity и
ledger key не менялись: обновление не заставляет повторять старый импорт и не
перемещает личные файлы. Слоты и исходная иерархия сохраняются внутри даты.

MovieStream — SDK модуль без Qt, живущий в CameraBrowser. Worker владеет lifecycle,
SDK callback только передаёт копию данных/состояния через ограниченные очереди.
FFmpeg вынесен в отдельный процесс: локальные MP4/MOV/M4V и SDK поток используют
общий VideoPreview. Приватный QLocalServer/AF_UNIX канал с обратным давлением
отделяет двоичные видеобайты от текстового протокола. SDK stream не публикуется
под именем оригинала, тайно копировать тяжёлый MP4 для просмотра приложение не
пытается. Stop подтверждается до освобождения SDK операции; отказ ведёт к reconnect.
Во время movie отключены конфликтующие кнопки камеры; прежний Live View восстанавливается.

VideoPreview выводит кадры в исходном размере/частоте без звука. С 0.6.1 удалены
scale/fps и MJPEG-перекодирование: FFmpeg выдаёт RGB24 в бинарном PPM, Qt разбирает
короткий заголовок и копирует завершённый кадр в QImage. Предел кадра — 128 MiB,
размер проверяется до создания изображения. Для локального файла фильтр realtime
задаёт темп по PTS декодированных кадров: входной -re давал начальный рывок при
отрицательных DTS/pre-roll короткого клипа. Предел коррекции часов 0,2 с позволяет
возобновиться после SIGSTOP/SIGCONT без долгого ускоренного догоняния. Ни один
полностью полученный кадр не отбрасывается парсером.
Первый кадр для галереи — PNG исходного размера, миниатюры уменьшаются отдельно.
Кнопки play/pause/stop/seek входят в ImageViewer и остаются в fullscreen вместе с
клавишами отбора. Локальная галерея получает видео отдельно от фотографии с тем же
именем, первый кадр/метаданные читаются в фоне, воспроизведение включается явно.
Внешний FFmpeg — системная зависимость DEB; GUI/SDK не связываются с его библиотеками.

Первичные источники: API Reference Sony SDK 2.02,
`class/contents_transfer_with_remote_control.html` (MP4, Thumbnail/Screennail),
`op_flow_and_seq/op_movie_playback.html`, `api_reference/movie_playback.html`,
`function_list/api_list.html` (SetMoviePlaybackSetting — ILCE-6700). SDK документация
и библиотеки в Git не добавлялись. Возможность streaming реализована по контракту;
проверка на физической камере остаётся отдельной от синтетического H.265.

В 0.6.1 аппаратная диагностика обнаружила UFW BLOCK входящего TCP от камеры на
55001: успешные Start/Play и StatusChanged не означали получение видео. Пустой
поток теперь даёт структурированную ошибку movie-no-data с адресами; GUI переводит
её и указывает порты/справку. FFmpeg запускается только с первыми байтами, поэтому
ошибка пустого input не маскирует причину SDK/сети. Нормальное окончание дочитывает
очередь callback до закрытия сокета. Подготовка ограничена 20 с, остальные отмены
остаются прерываемыми; Stop подтверждается до следующей операции. Обработаны оба
варианта callback OnWarning/OnWarningExt. Установка не правит брандмауэр.

Путь в QStatusBar — постоянное read-only поле: для локального файла абсолютный,
для карты исходный filePath SDK без подмены временным путём миниатюры. Поле
