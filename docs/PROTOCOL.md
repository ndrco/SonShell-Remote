# GUI ↔ SonShell: REMOTE/1

GUI запускает backend этого проекта через QProcess (stdin/stdout pipes):

```
sonshell --gui --auth-env --host <IPv4> --model <alias> --sync-dir <directory> --liveview-file <private-path> --camera-cache <private-directory>
```

`--gui` использует построчный ввод с poll, сохраняя обычный интерактивный libedit
режим CLI. Обычный CLI сохраняет старые команды. В --gui sync-команды, кроме sync off,
отвергаются: GUI использует явный card copy. `--version` не инициализирует SDK.
GUI добавляет каталоги backend и CrAdapter в LD_LIBRARY_PATH только дочернего
процесса: это нужно для transitive dlopen библиотек Sony.
GUI не использует `--keepalive`: повторные подключения принадлежат CameraSession.

Имя и пароль передаются переменными `SONSHELL_CAMERA_USER` и
`SONSHELL_CAMERA_PASSWORD`; backend читает и unsetenv до Init. argv и журнал GUI
не содержат пароль. Окружение процесса всё ещё доступно привилегированным локальным
инструментам; это не шифрованный канал хранения секретов.

## Состояния

Полная строка события, включая стабильную оболочку логгера (LF в конце):

```
INFO  | [INFO] REMOTE/1 connecting
INFO  | [INFO] REMOTE/1 connected
INFO  | [INFO] REMOTE/1 disconnected
INFO  | [INFO] REMOTE/1 liveview-started
INFO  | [INFO] REMOTE/1 liveview-stopped
INFO  | [INFO] REMOTE/1 liveview-failed
```

`connected` публикуется только после SDK handshake, `disconnected` — из callback
SDK. Остальные строки диагностические, не определяют состояние камеры.
GUI буферизует незавершённые строки, удаляет ANSI, принимает только полное совпадение
события; частичная read() не теряет событие. Секреты редактируются в копии для лога,
чтобы пароль со значением `connected` не ломал обработку протокола.

Кнопки доступны только в Connected. При завершении процесса/обрыве GUI сбрасывает
Live View и повторяет запуск с задержкой 3/6/12/24/30 с, если это включено.
При успехе задержка сбрасывается. Timeout первоначального подключения — 45 с.
«Отключить» отменяет таймер, отправляет quit и закрывает stdin. Через 1,5 с — TERM,
ещё через 1,5 с — KILL. Ожидание не блокирует основной цикл Qt.

## Live View

`monitor start` с `--liveview-file` получает JPEG из SDK в отдельном потоке без
OpenCV. До 15 кадров/с, буфер ограничен 32 MiB. Сначала запись `<path>.part`, затем
атомарный rename. Только последний кадр, файл и каталог принадлежат текущему сеансу.
Qt проверяет обновления каждые 70 мс; при ошибке чтения ждёт следующий кадр.
`monitor stop` и завершение соединения останавливают поток до ReleaseDevice.

Это локальный транспорт прототипа. Асинхронный бинарный сокет и отдельный канал
прогресса передачи можно добавить в REMOTE/2 без изменений виджетов просмотра.

## Расширения 0.3: готовые файлы и прогресс

```
INFO  | [INFO] REMOTE/1 transfer-progress <0..100> <hex-UTF8-absolute-path>
INFO  | [INFO] REMOTE/1 download-complete <new|sync> <hex-UTF8-absolute-path>
```

Путь кодируется lowercase hex, поэтому пробелы, Unicode и переводы строк в имени
не нарушают границы событий. GUI проверяет формат, диапазон процентов и размещение
в заданном каталоге снимков. `download-complete` выдаётся после атомарной публикации,
а не при обнаружении файла на диске. `new` — Auto Sync по событию камеры, `sync` —
ручная загрузка/Sync All. В 0.3 `new` запускал студийный показ. Начиная с 0.4 GUI не использует
эту цепочку и не запускает Auto Sync.

Все SDK передачи сериализованы: callback без transfer ID всегда относится к
одному активному файлу. Staging уникален для передачи и находится на той же ФС.
При публикации существующий финальный путь не перезаписывается. `sync stop`
сохраняет владение текущей передачей до terminal callback SDK; это исключает
поздний callback отмены после запуска следующего файла. Возобновление после
сбоя выполняется повторной загрузкой отсутствующего файла, без byte-range resume.


## Расширение 0.4: карта камеры

Команды (одна строка на файл/кадр; GUI посылает следующую после результата):

```
card list <request-id>
card preview <request-id> <epoch> <slot> <content-id> <file-id> <screen|thumb>
card copy <request-id> <epoch> <slot> <content-id> <file-id> <hex-UTF8-destination-directory>
card delete <request-id> <epoch> <slot> <content-id>
card cancel
```

ID состоит из ASCII букв/цифр/дефиса, максимум 80 символов; GUI добавляет UUID
сеанса. Epoch равна request-id последнего list. Переподключение сбрасывает очередь.
Старые эпохи отвергаются. Worker backend принимает не более 8 ожидающих запросов,
GUI держит остальную очередь у себя. При ошибке удаления очередь прекращается.

Строка ответа: `INFO  | [INFO] REMOTE/1 card <lowercase-hex-UTF8-JSON>`. Объект
имеет `type` и `request`. Каждая запись каталога отдельная (до 60 000 hex символов),
не один JSON всей карты. GUI разбирает эти строки отдельно, не печатая JSON в лог.

| type | Поля и смысл |
|---|---|
| changed | request пустой; карта изменилась, передачи не запускаются |
| begin | epoch, начало snapshot |
| item | epoch, slot, id, stamp (UTC), identity, protected, deletable, files |
| end | epoch, stale; конец каталога |
| slot-error | slot, message; недоступный/неподдерживаемый слот, затем end |
| progress | percent 0..100 для активной передачи |
| preview | path в --camera-cache, size; только compressed transfer, оригинал не запрашивается |
| copied | path, size; только проверенный и опубликованный оригинал |
| deleted | terminal OnWarningExt DeleteContent OK для точного content/slot |
| error | message; операция неуспешна, поздний успех не имитируется |
| fatal | message; продолжать transfer на этом соединении нельзя, перезапустить backend |

files — массив объектов `{id, format, size, path}`. size — десятичная строка,
чтобы не терять uint64 в JSON. Числовые format соответствуют SDK (JPEG 0x3801,
RAW 0xB101, HEIF 0xB110); сопутствующие файлы остаются в составе кадра. До 0.6 список
содержал только фотографии; начиная с 0.6 включает MP4 (см. ниже). id/contentId ограничены uint32.
identity формируется из доступного serial (иначе model+host), слота, даты и
путей/размеров; это метаданные для журнала импорта, не хеш оригинала.

При недоступном compressed API возвращается error, без fallback на оригинал.
Копирование и превью разделены от старого download-complete. GUI проверяет
приватный путь превью/назначение копии, состояние сеанса и request ID; неизвестные
или устаревшие события не меняют выбранный кадр/состояние операции.

## Расширение 0.5: доступные параметры и точка AF

```
controls list <request-id>
controls set <request-id> <property-code-decimal> <value-decimal>
controls af <request-id> <x-0..639> <y-0..479>
```

Команды доступны только GUI backend. `request-id` — 1–80 ASCII букв/цифр/дефисов;
GUI использует UUID и принимает только результат текущего запроса. Ответ:
`INFO  | [INFO] REMOTE/1 controls <lowercase-hex-UTF8-JSON>`.

- `snapshot`: `request`, `properties` и `af` (bool). Каждый параметр:
  `{name, code, readable, writable, current, current_label, values:[{value,label}]}`.
  Числовые значения — десятичные строки без потери uint64; code — uint32.
  Стабильные name: `focus_mode`, `focus_area`, `white_balance`, `drive_mode`,
  `iso`, `shutter`, `aperture`, `ev`. current_label — отображение текущего
  значения, включая значение вне списка доступных для записи.
- `applied`: `request`; SetDeviceProperty вернул успех. Это принятие настройки,
  а не подтверждение резкости или неизменности значения после callback камеры.
- `error`: `request`, `message` (диагностический код). Ошибка не считается успехом.
- `INFO  | [INFO] REMOTE/1 controls-changed`: callback свойств. GUI объединяет
  уведомления таймером и перечитывает snapshot, когда нет операции с картой.

Allow-list backend ограничивает set указанными восемью свойствами. Перед каждым
set заново проверяются IsSetEnableCurrentValue, тип UInt16/32Array или Int16Array
и GetValues. Для EV wire-значение — беззнаковое представление младших 16 бит
(например -333 → "65203"), с восстановлением знака перед SDK set. Экспозиция
записывается со скалярным типом UInt32/UInt16/Int16, как в CLI exposure.
GetSetValues/GetSetValueSize зарезервированы в API 2.02 и не используются.
Свойства без списка вариантов остаются недоступными для записи. Snapshot ограничен
29 000 байт до hex; слишком большой ответ становится error.

AF использует AF_Area_Position: x в старших 16 битах, y в младших. Наличие
свойства и возможность записи проверяются непосредственно перед set. Границы
сужаются на половину размера рамки из LiveViewProperty/CrFocusFrameInfo;
при нескольких рамках берётся консервативное пересечение. Без достоверных
метаданных рамки AF отключён. Точки вне границ отвергаются, режим экспозиции
и область фокуса автоматически не переключаются. С 0.6.2 команда после успешной
установки точки выполняет S1 Locked → 1 с → Unlocked, без полного спуска. До
записи проверяются режим AF-S/AF-C/AF-A/AF-D/DMF и доступность S1; в MF/PF AF
недоступен. Snapshot af учитывает эти условия. S1 не добавляется в allow-list set.
RAII освобождает полунажатие при ошибке запуска и повторяет неудачное отпускание.
Ошибка установки точки не запускает AF. af-press:<SDK> означает, что точка уже
перемещена, но запуск AF отклонён; af-release:<SDK> — отпускание не подтверждено.
Applied приходит после отпускания, не подтверждает оптическую резкость.

GUI преобразует координату через mapToScene/mapFromScene текущего изображения;
поля исключаются, zoom и pan учитываются. Live View показывается в координатах
JPEG SDK без дополнительного поворота/зеркалирования. Соответствие ориентации
и границ на каждой физической модели остаётся аппаратной проверкой.

Тайм-аут GUI запроса — 7 с, устаревшие ответы игнорируются. После set GUI перечитывает
значения камеры, в том числе при отказе; диагностическое сообщение сохраняется.
JSON параметров не печатается в пользовательский журнал. Старые команды CLI,
протокол карты и порядок передачи оригиналов не изменены.

## Расширение 0.6: видео и дата съёмки

Каталог `card list` больше не исключает записи MP4 (SDK format 0xB982).
Сопутствующие XML (0xBA82), прокси и остальные файлы остаются частью записи;
удаление по content-id касается всей записи. Фильтр «видео» выбирает записи
с MP4 и копирует их состав, «фото» — остальные медиазаписи; RAW/JPEG — файлы
соответствующего формата. При `card preview ... screen` MP4 принудительно
использует Thumbnail: Screennail не поддерживается SDK для видео. Команда screen
не загружает оригинал; отдельный режим original добавлен в 0.7.1.

`item` дополнительно содержит `capture_date`: YYYY-MM-DD из
creationDatetimeLocaltime камеры. При недостоверной локальной дате используется
валидная creationDatetimeUTC; иначе `Unknown-Date`. Число дней месяца и високосный
год проверяются. Новые оригиналы публикуются под
`destination/capture_date/Slot_N/relative-camera-path` с прежними проверками
symlink/выхода за корень, размера, атомарности и отсутствия перезаписи.
Дата компьютера не используется. Старые ledger записи и файлы не перемещаются;
New/Selected продолжают учитывать подтверждённые копии в старой структуре.
Передача оригинала прерывается по 3 минутам без callback SDK, а не по общей
длительности 10 минут: большой ролик с поступающими уведомлениями не обрывается
из-за фиксированного лимита времени. Явная отмена по-прежнему ждёт terminal callback.

### Потоковый просмотр

```
card movie <request> <epoch> <slot> <content> <MP4-file-id> <hex-UTF8-local-socket-path>
card movie-play <request>
card movie-pause <request>
card movie-seek <request> <seconds-0..86400>
card cancel
```

GUI заранее создаёт QLocalServer в приватном camera-cache. Backend проверяет,
что UNIX socket находится непосредственно в этом каталоге. Исходящие видеобайты
SDK передаются только по этому каналу; stdout остаётся текстовым REMOTE/1.
IP компьютера определяется маршрутом к IPv4 камеры через getsockname UDP socket,
без отправки датаграммы. SDK SetMoviePlaybackSetting получает slot/content/file,
адрес и стандартные порты SDK. Monitor останавливается до запуска movie,
EnableLiveView выключается. Start ждёт StatusChanged, затем Play. Пауза и seek
выполняются worker; callback не вызывает управляющие функции SDK. Seek передаётся
в единицах 1/100 с. Команды управления проверяют request активного просмотра.

Ответы канала `REMOTE/1 card <hex-JSON>`:

- `movie-state`: request, state (`preparing`, `playing`, `paused`). Состояния
  playing/paused означают принятую SDK команду; ошибочный результат возвращается error.
- `movie-stopped`: StopComplete/нормальное завершение подтверждены SDK.
- `error`: отказ/нет данных/закрытие канала/сбой декодера; успех не имитируется.
- `fatal`: SDK не подтвердил остановку, дальнейшие операции требуют нового backend.

Очередь потока ограничена 8 MiB, отдельный пакет 4 MiB. Callback копирует данные
и будит worker; он отправляет их с контролем обратного давления, без блокировки SDK
callback и без записи оригинала на диск. Старт ожидает 20 с, отсутствие видеоданных
12 с (пауза исключена), непринимающий декодер 5 с, StopComplete 5 с. Просмотр
сериализован с передачами/удалением. Неподтверждённый Stop приводит к fatal/reconnect,
чтобы поздние callback не попали в следующий просмотр.

GUI запускает отдельный FFmpeg с первыми байтами, получает RGB24/PPM кадры исходного размера/частоты и показывает
их через ImageView с обычным масштабом/fullscreen/оверлеем. Звук в этом предпросмотре
не выводится. Память входа/выхода ограничена; ошибки декодирования видимы. После
EOF декодер дочитывает буфер. Переход к другой записи останавливает текущий поток,
затем запрашивает последнее выбранное превью. Отбор Space/Delete доступен и во
время просмотра видео; копирование/удаление требуют остановить поток. Переход на
другую вкладку прекращает movie; прежний Live View восстанавливается после остановки.

Поддержка SetMoviePlaybackSetting для ILCE-6700 отмечена в таблице API Reference
2.02. Реальные SDK streaming/прошивка/сеть требуют аппаратной приёмки; фикстуры
H.265 проверяют транспорт/декодер, но не подтверждают работу физической камеры.

С 0.6.1 error может содержать `code: "movie-no-data"`, `camera_host`, `computer_ip`:
GUI выводит перевод с адресами и входящими TCP 55001/55003/55005. Нормальное
окончание без видеобайтов считается ошибкой, а не успешным просмотром. При EOF
очередь уже полученных SDK пакетов дописывается перед закрытием локального канала.

### Дополнения 0.7: SHA256 и студийный JPEG

- copied включает sha256: 64 строчных hex-символа, сумма всего staged-файла
  после Result_OK/проверки размера и до публикации. Это эталон полученной копии;
  эталонный хеш камеры в этом API недоступен.
- progress может содержать phase: "hash", percent 0–100. GUI отображает передачу
  как 0–90%, хеширование 90–99%, публикацию/ledger — до 100%. card cancel отменяет
  и хеширование; непроверенный staged-файл не публикуется.
- `card preview <request> <epoch> <slot> <content> <file> jpeg` получает исходный
  JPEG в camera-cache через GetRemoteTransferContentsDataFile. Только JPEG до
  128 MiB, без RAW/MP4. Проверки идентичности прежние; ответ preview тот же.
  После декодирования GUI удаляет временный файл.
- Очередь продолжения и проверка локальных сумм реализованы в GUI; новых команд
  повтора спуска/удаления SDK нет. После reconnect читается новый epoch и
  сопоставляются стабильные идентичности сохранённого плана.

### Дополнение 0.7.1: оригинал для просмотра карты

`card preview <request> <epoch> <slot> <content> <file> original` передаёт выбранный
JPEG/RAW/HEIF/MP4 через GetRemoteTransferContentsDataFile в приватный camera-cache.
Формат определяет расширение `.jpg/.arw/.hif/.mp4`, не путь камеры. Нулевой размер
и сопутствующие файлы отвергаются. До передачи проверяется свободное место
для файла с запасом 64 MiB; staged/publish, сверка размера, отмена и идентичность
каталога такие же, как у импорта. Ответ — preview, без copied/ledger/SHA256.

GUI декодирует оригинал в QtConcurrent с отменой: JPEG в исходном размере,
RAW — лучший встроенный JPEG через ExifTool, MP4 — первый кадр и затем локальный
FFmpeg без уменьшения/повторного сжатия. Фото JPEG автоматически запрашивается
при выборе строки в стандартном качестве; RAW/видео — только отдельной кнопкой.
Качество студии независимо. Быстрый режим использует прежние screen/thumb.
Один последний оригинал хранится в кеше до замены/отключения; импортированная
подтверждённая копия используется напрямую и никогда не удаляется этим механизмом.
При смене строки локальный проигрыватель останавливается; устаревшие результаты
не подменяют выбранный кадр. Отмена декодирования не отправляет SDK-команду.

CrMoviePlaybackSetting SDK 2.02 не содержит полей разрешения/битрейта. Размер
SDK-потока определяется камерой (ILCE-6700 ранее отдала 1280×720); просмотр
оригинала требует отдельной полной передачи и не выдаётся за повышение качества потока.

## 0.8: параметры записи

Формат controls list/set не меняется. Snapshot может содержать дополнительные
имена (code всегда приходит от SDK, не задаётся в GUI):

| name | Свойство SDK |
| --- | --- |
| file_type | FileType: RAW/JPEG/RAW+JPEG/HEIF |
| compression_format | CompressionFileFormatStill: JPEG/HEIF |
| image_quality | StillImageQuality |
| image_size | ImageSize |
| aspect_ratio | AspectRatio |
| raw_compression | RAW_FileCompressionType |
| steady_still | ImageStabilizationSteadyShot |
| movie_format | Movie_File_Format |
| movie_framerate | Movie_Recording_FrameRateSetting |
| movie_setting | Movie_Recording_Setting |
| steady_movie | Movie_ImageStabilizationSteadyShot |

Choices читает UInt8Array/UInt16Array/UInt32Array и прежний Int16Array EV,
не трактуя byte 128–255 как отрицательный. Неверная длина массива/тип отключают
запись. Для перечислений setter сохраняет ValueType, полученный от SDK (как
в CameraDevice.cpp Sony 2.02); прежние scalar setters экспозиции сохранены.

StillImageStoreDestination и другие невыведенные свойства через set недоступны.

current_label и values.label новых свойств генерируются из enum локального SDK
при сборке; неизвестное этому SDK значение показывается hex без придумывания
смысла. Applied подтверждает вызов SDK, после него GUI ждёт нового Snapshot
перед следующим изменением. Зависимые значения меняет камера; GUI не отправляет
цепочки setter и не воспроизводит настройки при reconnect. Автоподключение при
запуске — настройка GUI, протокол команд SDK не меняет.
