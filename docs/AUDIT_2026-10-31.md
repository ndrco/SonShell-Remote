# Аудит пожеланий — 2026-10-31

После этого аудита пользователь поручил публикацию: репозиторий
[ndrco/SonShell-Remote](https://github.com/ndrco/SonShell-Remote) создан и наполнен.
Проверки и границы публикации описаны в [PUBLISHING.md](PUBLISHING.md).
Раздел о GitHub ниже фиксирует состояние до этой отдельной команды.

Проверена версия 0.8.3, исходный коммит `0817207`. Сверены исходное задание,
последующие уточнения пользователя, ROADMAP, GUI/backend и сохранённые результаты
аппаратных и установочных проверок. В этом аудите камера не использовалась.

Основной сценарий фотографа реализован: съёмка без автоматической передачи RAW,
отбор на карте, удаление брака с подтверждением и явный импорт. Все задумки
закрыты не полностью: остаются другие Ubuntu/архитектуры, остальные функции SDK,
ограничения студийного просмотра и прямого видеопотока, расширенная приёмка.

«Реализовано» ниже означает наличие кода и проверок соответствующего пути,
а не гарантию для каждой камеры, карты, объектива и системы.

## Что остаётся по исходным задумкам

1. **Матрица установки Ubuntu.** Текущий пакет нельзя считать универсальным.
   Нужны отдельные сборки и чистые проверки выбранных других версий/архитектур
   с совместимым Sony SDK. Установка 24.04 amd64 уже выполнена и подтверждена.
   Изолированная установочная проверка offscreen не заменяет приёмку разных
   графических сеансов и оборудования.
2. **Расширенное управление камерой.** За пределами текущего набора остаются,
   например, профили изображения/цвет, S&Q, аудиопараметры и другие функции SDK.
   Соответствие Creators' App целиком не реализовано и не подтверждено.
3. **Студийное полное разрешение.** Исходный JPEG работает при наличии JPEG
   на карте, включая RAW+JPEG. RAW-only не даёт такой же режим; прямой PostView
   не используется. Сейчас новый кадр определяется через перечитывание каталога.
   Задержки и поведение физических серий/аппаратного спуска требуют замеров.
4. **Прямой SDK-видеопоток.** В 0.6.1 он работал на ILCE-6700, но в 0.8.1
   два ролика дали аудио без видеокадров при принятых TCP-соединениях. Причина
   не установлена. Рабочий основной путь — полный оригинал/кеш; для больших
   роликов это ожидание передачи до начала просмотра. Новая перемотка SDK
   опирается на оценку позиции декодера, а не на timecode камеры, и не прошла
   аппаратную приёмку 0.8.3.
5. **Приёмка текущей версии на камере.** Нужны реальные серии, большие очереди
   RAW+JPEG/видео с обрывами, новые fullscreen-кнопки и отмена, режимы/объективы AF
   и экспозиции. Автоматические проверки и прежние аппаратные прогоны не заменяют
   такую приёмку. Второй слот не является требованием к однослотовой камере пользователя.

## Оставшееся развитие из дорожной карты

Это отдельные улучшения, а не все обязательные пункты исходного задания:

- Большие карты: профилирование, виртуальный список и обновление изменённых строк.
  Сейчас карта использует QTreeWidget и пересоздание строк; студия читает каталог.
- Secret Service/keyring вместо пароля в INI. Текущий флажок и права 0600/0700
  уже реализованы; системное хранилище ещё не используется.
- CI для GUI/тестов/выпуска; SDK-проверки в отдельном окружении. В репозитории
  есть локальные скрипты и тесты, но нет workflow CI.
- USB и обнаружение камер в GUI, несколько камер. Backend умеет enumeration,
  а GUI требует один IPv4 и обслуживает один сеанс.
- Проявление RAW и звук видео. Сейчас RAW показывается через встроенный JPEG,
  воспроизведение без звука; при копировании оригинальные файлы сохраняются целиком.
- Независимая контрольная сумма с камеры и докачка внутри файла. SHA256 локального
  содержимого, проверка копий и сохранение/продолжение очереди уже есть с 0.7;
  незавершённый файл передаётся заново. По принятому решению для используемого
  RemoteTransfer SDK 2.02 диапазоны/offset недоступны.

в рамках аудита не выполнялись. Полная аппаратная приёмка перед стабильным
выпуском остаётся открытой.
