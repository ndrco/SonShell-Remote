# Разработка

1. Перед изменением описать задачу и критерии готовности в issue или pull request.
2. Менять GUI и SDK bridge независимо; протокол описывать в docs/PROTOCOL.md.
3. Проверить GUI без SDK и backend с доступной версией SDK — docs/BUILD.md.
4. Добавлять поведенческие тесты для состояний/ошибок, использовать fake backend;
   реальные камеры и пароли не должны требоваться CTest.
5. Обновить CHANGELOG.md, архитектурные решения и фактические результаты TESTING.md.
6. Коммитить логические изменения: gui:, backend:, package:, docs:, test:.
7. Выпуск DEB проверять в чистом образе Ubuntu без SDK и рабочего дерева.

Рабочие каталоги build*/ не входят в Git. SDK не публиковать; снимки и настройки
не добавлять как fixtures. До публичного стабильного выпуска необходима аппаратная
приёмка: соединение, съёмка, Live View, RAW+JPEG, обрыв сети и восстановление.
